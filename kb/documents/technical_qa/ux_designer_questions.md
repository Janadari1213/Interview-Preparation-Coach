## Q: What is Nielsen's Heuristic Evaluation and why is it used in UX design?

**Topic:** UX Heuristics & Usability  
**Role:** UX Designer  
**Difficulty:** medium  
**Q:** What is Nielsen's Heuristic Evaluation and why is it used in UX design?  
**A:** Nielsen's Heuristic Evaluation is a usability inspection method where evaluators examine an interface against 10 general principles of interaction design (e.g., Visibility of system status, Match between system and real world, User control and freedom, Consistency and standards, Error prevention). It rapidly identifies usability flaws early in design cycles without full user testing budgets.

## Q: What is the difference between Low-Fidelity and High-Fidelity Prototyping?

**Topic:** Prototyping & Wireframing  
**Role:** UX Designer  
**Difficulty:** easy  
**Q:** What is the difference between Low-Fidelity and High-Fidelity Prototyping?  
**A:** **Low-Fidelity Prototyping** (e.g., paper sketches, wireframes) focuses on layout, information architecture, and core user flows quickly and cheaply. **High-Fidelity Prototyping** (e.g., interactive Figma/Framer prototypes) incorporates realistic visual design, micro-interactions, exact typography, and actual copy to test micro-usability before front-end implementation.

## Q: What are the principles of Web Content Accessibility Guidelines (WCAG) under the POUR framework?

**Topic:** Accessibility (a11y)  
**Role:** UX Designer  
**Difficulty:** hard  
**Q:** What are the principles of Web Content Accessibility Guidelines (WCAG) under the POUR framework?  
**A:** **POUR** stands for: 1) **Perceivable**: Information must be presentable in ways users can perceive (e.g., alt text for images, high color contrast). 2) **Operable**: Interface components must be keyboard accessible. 3) **Understandable**: Information and navigation must be predictable and intuitive. 4) **Understandable**: Content must remain robust across diverse screen readers and assistive devices.

## Q: What is Information Architecture (IA) and how do Card Sorting exercises help construct it?

**Topic:** Information Architecture  
**Role:** UX Designer  
**Difficulty:** medium  
**Q:** What is Information Architecture (IA) and how do Card Sorting exercises help construct it?  
**A:** Information Architecture is the structural organization and labeling of web content to enable intuitive navigation. **Card Sorting** is a user research technique where participants organize content items into logical groups and label categories. Open sorting informs category creation, while closed sorting tests pre-defined navigation structures.

## Q: What is the difference between UX Design and UI Design?

**Topic:** UX Foundations  
**Role:** UX Designer  
**Difficulty:** easy  
**Q:** What is the difference between UX Design and UI Design?  
**A:** **UX (User Experience) Design** focuses on overall system structure, user flows, usability research, wireframing, and solving functional user pain points. **UI (User Interface) Design** focuses on visual polish, color palettes, visual hierarchy, typography, iconography, and interactive visual states (hover/active states).

## Q: How do you conduct Moderated vs Unmoderated Usability Testing?

**Topic:** User Research Methods  
**Role:** UX Designer  
**Difficulty:** medium  
**Q:** How do you conduct Moderated vs Unmoderated Usability Testing?  
**A:** **Moderated Testing**: A researcher directly guides the participant live, asking probing questions to understand thought processes during tasks. **Unmoderated Testing**: Participants complete tasks independently via automated platforms (e.g., UserTesting) following prompt scripts, enabling fast, quantitative completion rate data across larger sample sizes.

## Q: What is a Design System and why is it important for product scaling?

**Topic:** Design Systems & Tokens  
**Role:** UX Designer  
**Difficulty:** hard  
**Q:** What is a Design System and why is it important for product scaling?  
**A:** A Design System is a comprehensive suite of reusable design assets, UI components, brand guidelines, typography scale, and coded design tokens. It ensures visual consistency across web and mobile products, reduces design/engineering redundancy, and accelerates product development velocity during team scaling.

## Q: What is a User Journey Map and what key components should it contain?

**Topic:** User Research & Journey Mapping  
**Role:** UX Designer  
**Difficulty:** medium  
**Q:** What is a User Journey Map and what key components should it contain?  
**A:** A User Journey Map visualizes the step-by-step end-to-end process a user undergoes to accomplish a goal. Key components: 1) Persona & Scenario context. 2) Timeline phases (Awareness -> Consideration -> Action -> Onboarding). 3) User Actions & Touchpoints. 4) User Thoughts & Emotional sentiment curve. 5) Opportunities & UX pain points identified for improvement.

## Q: What is Fitts's Law and how does it apply to interactive UI design?

**Topic:** UX Psychology & Interaction Design  
**Role:** UX Designer  
**Difficulty:** hard  
**Q:** What is Fitts's Law and how does it apply to interactive UI design?  
**A:** Fitts's Law states that the time required to rapidly move to a target area is a function of the ratio between the distance to the target and the width of the target ($MT = a + b \log_2(2D/W)$). In UI design: 1) Make primary Call-To-Action (CTA) buttons large and prominent. 2) Position interactive targets close to cursor/thumb hotspots (e.g., bottom navigation bars on mobile).

## Q: How do you handle feedback from engineers when a design is flagged as technically infeasible?

**Topic:** Cross-functional Collaboration  
**Role:** UX Designer  
**Difficulty:** medium  
**Q:** How do you handle feedback from engineers when a design is flagged as technically infeasible?  
**A:** 1) Seek to understand technical constraints (e.g., API limitations, render performance, build deadline). 2) Collaborate early during low-fidelity wireframing to spot blockers. 3) Co-create alternative solutions or simplified micro-interactions that preserve the core user experience and usability goals without inflating engineering complexity.
